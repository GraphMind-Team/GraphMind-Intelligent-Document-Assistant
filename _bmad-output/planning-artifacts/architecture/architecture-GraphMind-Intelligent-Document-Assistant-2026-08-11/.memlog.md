- (decision) Ingestion consistency: compensating rollback (saga-lite). Postgres documents row tracks FR-4 status ladder (Uploaded->Extracting->Graphing->Ready/Failed). On second-write failure (Weaviate or Neo4j), the handler actively deletes whatever the first write already committed, so no orphaned partial state survives a failed ingestion. User chose this over the simpler no-rollback option explicitly to avoid orphans.
- (decision) Deployment: Vercel Hobby (free) for React frontend; Render free web service (750 instance-hrs/mo, 15-min idle spin-down) for FastAPI backend. Verified current as of Aug 2026.
- (question) Weaviate Cloud's free tier is a 14-day auto-expiring sandbox (data deleted on expiry), not a stable free tier like Neo4j AuraDB Free / Neon Free - verified web research Aug 2026
- (decision) Deferred to post-v1: permanent/stable Weaviate hosting (self-host vs paid tier vs alternative). For the 20-day build, use the free sandbox and recreate/re-ingest if it expires mid-development - acceptable since ingestion is already a repeatable scripted pipeline. Must be resolved before relying on this for a live, ongoing portfolio demo.
- (decision) Tenancy enforcement: shared data-access layer (repository functions, e.g. get_documents(user_id,...)) that every module/handler must call for Weaviate and Neo4j reads/writes - no module hand-writes raw queries against these stores directly. Chosen over handler-level trust specifically because tenancy isolation is the PRD's one launch-blocker requirement (SM-3) and must hold structurally, not by convention, across 2 developers working in parallel.
- (decision) API contract: Pydantic response_model per route for success responses; FastAPI default HTTPException(status_code, detail) for all error paths - single consistent {"detail": ...} error shape, no custom envelope.
- (decision) Entity identity resolution (FR-5): exact string match only. 'TechCorp' and 'TechCorp Supplies' remain distinct graph nodes - no fuzzy/LLM-assisted merge in v1. Simplest, deterministic, avoids false-merge risk.
- (decision) Frontend state management: React Context API, not Redux. Shared state surface is small (auth/user, theme preference, chat document-scope selection) - doesn't justify Redux's boilerplate/tooling at this scale.
- (decision) Shared LLM-client wrapper: one module wraps OpenRouter calls (API key/base URL/model config, retry/timeout handling), used by both entity-extraction (documents module) and answer-generation (chat module) - no module calls OpenRouter directly. Also the natural enforcement point for FR-10's refusal short-circuit before generation.
