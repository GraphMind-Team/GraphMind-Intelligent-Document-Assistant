## Checklist walkthrough

**Divergence points fixed / none missed.** AD-1 through AD-8 each name a concrete two-developer divergence risk (rollback ambiguity, raw-query tenancy bypass, inconsistent error envelopes, fuzzy vs exact merge, Redux vs Context, direct OpenRouter calls, hosting assumptions, staging sprawl) and each Rule is a mechanical, checkable constraint (single wrapper module, single response shape, exact-match only, etc.) — not aspirational language. This is the spine's strongest area.

**One real miss: FR-5's entity/relationship type list.** The PRD (§8, open question #1) explicitly assigns "exact entity/relationship type list for extraction" to architecture to resolve ("belongs to architecture, flagged here so it isn't lost"). The spine's Deferred section punts it back unresolved ("flagged in the PRD... but not resolved in this coaching session... genuine open item, not invented here"). This is a genuine two-developer divergence point squarely inside this altitude's remit (whole-product, build-substrate, PRD explicitly delegated it) — whoever writes the extraction prompt and whoever writes the merge/graph-read logic need the same fixed vocabulary (e.g. project/team/technology/person), or entities silently fail to align. Deferring it to "before extraction prompts can be finalized" without naming even a draft list leaves exactly the kind of divergence this altitude is supposed to close. **Severity: Medium** — it's flagged (not silently dropped) and low-cost to fix later, but it is architecture's job per the PRD's own delegation, and this document is marked `status: final`.

**AD Rules are enforceable.** All 8 rules are structurally checkable (a reviewer or a linter could verify "every DAL call goes through shared/data_access/", "every route has a response_model", etc.) rather than relying on convention or memory. AD-2 in particular correctly notes it resolves SM-3 (the PRD's sole launch blocker) *structurally*, which is the right altitude call.

**Deferred section — no cross-unit divergence risk left in it, with one caveat.** Weaviate hosting punt (recreate/re-ingest sandbox) is safe because ingestion is already a scripted, idempotent pipeline per AD-1/AD-2 — two devs won't diverge on how to do it. Staging-environment punt is fine (AD-8 already forecloses it for v1). SM-1 numeric target and delete/graph-persistence UX are correctly pushed to PM, not architecture's to own. The one item that *shouldn't* have been left in Deferred is the FR-5 type list, discussed above — everything else in that section is legitimately out of scope or non-divergent.

**Ratifies rather than contradicts the PRD/addendum.** Cross-checked against `prd.md` and the memlog: every AD traces to either a PRD FR/SM citation or an explicit user decision recorded in `.memlog.md` (AD-1, AD-2, AD-4, AD-6, AD-7 all have matching memlog entries with the same rationale). No contradictions found — e.g., AD-4's exact-match choice matches PRD's FR-5 assumption note that identity-resolution mechanism was left to architecture, and the spine resolves it rather than re-opening it.

**Named tech currency (Aug 2026).** Weaviate Cloud's 14-day sandbox expiry and free-tier hosting facts are explicitly marked "verified web research, Aug 2026" in both the spine and memlog — good practice. However, several version pins (FastAPI 0.139.x, React 19.2.x, Vite 8.0.x, weaviate-client 4.22.0, neo4j driver 6.2) carry no such verification annotation or citation, unlike the Weaviate-expiry and Render/Vercel deployment facts which are explicitly called "verified current as of Aug 2026." This reviewer cannot independently confirm these version numbers are real released versions as of Aug 2026 (some, like FastAPI 0.139.x, are plausible extrapolations but unverifiable from the document alone). **Severity: Low** — doesn't block a 20-day portfolio build (pinning is easy to correct at `pip install`/`npm install` time), but the Stack table's presentation implies the same verification rigor applied to deployment facts was applied here, and that isn't evidenced.

**Whole-dimension coverage at this altitude.** Deployment/environments/infra is explicitly covered (AD-7, AD-8, deployment Mermaid diagram, environment-tier decision) — not silent, which is the most common failure mode this checklist calls out and it's handled well here. Other whole-product dimensions (data/tenancy model, API contract, state management, dependency direction, structural seed) are each decided. No dimension owned by this altitude was found silent.
