- (technique) started Yes And Building
- (idea by coach) Live entity/relationship preview shown right after ingestion, before first question
- (idea by user) Let user edit/correct what the graph extracted
- (idea by user) Bot must answer only from grounded document evidence, or explicitly say I don't know rather than hallucinate
- (idea by user) User can scope a question to a chosen subset of uploaded documents
- (decision by user) Graph is one unified graph across all of a user's uploaded documents, not per-document
- (idea by user) Cross-document Q&A mode: ask across all uploads at once, not just a scoped subset
- (idea by user) User can delete a document and all its traces vanish from both Neo4j and Weaviate
- (idea by user) Document library view listing all uploaded documents
- (decision by user) v1 supported document types: PDF, Markdown, HTML
- (technique) started Brain Writing Round Robin
- (idea by user) Query history: save question + answer pair per user, revisitable
- (decision by user) Reject confidence badge idea; park 'Explain this answer' reasoning trace for later consideration
- (technique) started Reverse Brainstorming
- (idea by coach) Failure mode: LLM answers ungrounded, from general world knowledge, indistinguishable from real grounding
- (idea by user) Failure mode: cross-user data leakage - LLM answers using another user's uploaded documents
- (decision by user) Hybrid Neo4j graph + Weaviate vector RAG is a hard v1 requirement, not something to spike/validate away
- (idea by coach) Failure mode: ingestion cost/latency spiral from re-processing unchanged docs - inverse: content-hash dedupe
- (idea by coach) Failure mode: Neo4j/Weaviate writes go out of sync on partial failure - inverse: unified ingestion job status tracking both writes
- (technique) started Laddering
- (insight by user) Laddering root need from citations: users want to trust the answer enough to skip reading the full documents themselves, citations are the verification shortcut not the goal
- (technique) started Disney Method
- (decision by user) Simplified deletion rule for v1: deleting a document removes it from the library/vector store but the knowledge graph itself is NOT retroactively pruned - avoids reference-counting complexity
- (decision by user) MoSCoW confirmed: Must = upload+graph+vectors, grounded Q&A with citations, doc library/status, delete (graph not pruned), per-user tenancy isolation. Should = doc scoping, content-hash dedupe, query history. Could = user graph edits, opt-in reasoning trace, ingestion preview. Won't-this-time = contradiction detection, correction-feed diagnostics, ref-counted delete, trust-display defaults
- (insight) North star: users must never need to read the source documents by hand - trust-through-citation is the reason the Must list looks the way it does. MoSCoW split is the chosen scope, kept as-is for the MVP.
